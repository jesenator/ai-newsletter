Top: Self-Sustaining AI Worms

  • Working prototype of a computer worm that hijacks compromised GPUs to run its own LLM inference Import AI 467 arXiv Toronto/Vector/Cambridge/ServiceNow: an open-weight LLM on a single A100 with no vendor API — so nothing to monitor or revoke. It scans, finds vulns (~80%), exploits (~53%), then self-replicates (88%) into a decentralized swarm with no single point of control; difficult hosts get retried by replicas sampling fresh reasoning paths. ~37% end-to-end. "Self-sustaining AI-driven cyber-threats are no longer theoretical." Extremely CivAI-shaped, and pairs directly with the escape incidents.
  • GovAI: the bottleneck for a WannaCry-scale AI worm is "elite exploits" X: Markus Anderljung GovAI Halstead & Frighetti: if frontier AI let a quarter of moderately skilled actors build zero-interaction, high-privilege exploits against widely used software, expert+forecaster estimates put marginal damages in the tens of billions/year and ~3× the odds of a single >$10B worm. Evidence: WannaCry and NotPetya both followed the 2017 NSA EternalBlue leak within months. Companion argument: OpenAI's $100B Preparedness threshold is the wrong trigger — $10B is the useful one.

Productivity & Practice

  • "Don't be a meat proxy" — stop relaying raw Claude output to humans gruhn.me HN (1322 pts) The most-upvoted thing on HN today, and a real norm worth adopting internally: pasting a giant model response into Slack or a PR review adds nothing — the recipient can prompt the model themselves and control the context better. Read it, validate it, write it in your own words; the rewrite is the certificate that you did. Related HN thread: manually retyping LLM-generated code to avoid cognitive debt (259 pts).
  • A critical CVE was issued for a hallucinated SQLite vulnerability JFrog HN (517 pts) LLM-generated slop made it through into the official CVE database with a critical severity rating. Small but sharp illustration of Matthew Green's point: verification, not generation, is now the bottleneck — and security infrastructure isn't ready.
  • Dwarkesh: compute may get 10x+ more expensive as models get smarter Import AI Dwarkesh Argument: a true human-level SWE running on one H100-equivalent implies that H100 should rent for >$250k/yr — 15× today's spot price. AI is cheap relative to labor mainly because it still can't do what top humans do. Relevant if you're thinking about how to position savings for a transformative-AI world: the "commodity" inputs get bid up long before roboticization brings them back down.
